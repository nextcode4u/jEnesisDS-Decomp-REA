# jEnesisDS BlocksDS Port C

The port compiles the project's ARM7 and ARM9 programs from C with Wonderful's compiler. It links against libnds and uses the standard BlocksDS startup code. The C core runs the 68000 and VDP diagnostic, boots Sonic the Hedgehog into Green Hill Zone Act 1, and starts Sonic the Hedgehog 2 in one-player Emerald Hill Zone Act 1 in melonDS. The touch menu provides two save slots. Cartridge games with battery-backed SRAM can also use their in-game save menus. The C Z80 executes Genesis sound drivers and handles YM2612 timer status. ARM7 mixes six-channel YM2612 FM, DAC samples, and PSG audio. YM2612 accuracy, broader game compatibility, and sustained full-speed emulation remain open.

## Build on Linux or WSL

Install Python 3, GNU Make, and the `blocksds-toolchain` package from Wonderful Toolchain. The C target was tested with BlocksDS 1.25.0. [BlocksDS Linux installation guide](https://blocksds.skylyrac.net/docs/setup/linux/)

From the repository root, run:

```sh
make
```

This compiles and links both CPUs into ELFs under `build/c/`, then packages them into `build/jEnesisDS-C.nds`. The fresh build requires only this checkout and the installed SDK and toolchain. Set `WONDERFUL_TOOLCHAIN` or `BLOCKSDS` to use a custom installation.

In melonDS, enable a virtual DLDI SD card and add Genesis ROMs to it. The bottom screen uses the original jEnesisDS menu artwork and font. The build converts the editable tile sheets, palettes, and tilemap into C. The footer shows the port's measured Genesis frames per second during gameplay.

In Configuration, **Horizontal View** controls how 320-pixel games fit on the 256-pixel DS screen. **Left** is the default and keeps the left edge visible using the tile renderer when supported. **Center** uses the original centered crop. **Fit** shows both edges using the bitmap renderer, which takes more CPU time. The option has no effect on 256-pixel games.

Fit can skip redraws under load so the game and audio keep advancing. The bottom-screen gameplay counter shows emulated frames per second. Configuration shows the most recent video update rate and whether the program launched in DS or DSi mode. In DSi mode it also shows the ARM9 clock setting.

In a 600-frame Sonic 2 Emerald Hill replay in melonDS, the faster bitmap renderer and redraw pacing sustained 59.83 game FPS and 30.31 video FPS with Fit in native DSi mode. At 67 MHz in DS mode, gameplay ran at about 54 FPS and the video updated about 11 times per second in the same interval. The bitmap renderer matched 1,800 frames from the previous implementation byte for byte in a host replay.

- In the ROM browser, use **Up** and **Down** to highlight an entry, **Left** and **Right** to change pages, **A** to open or run the selection, and **B** to open the parent folder.
- During emulation, touch the panel to pause and touch again or press **SELECT** to resume. Press **SELECT** while running or tap the cartridge icon to open the browser. Press **SELECT** in the browser to return to the current cartridge.
- Tap the controller icon to open configuration. Use **A** or tap **Country** to cycle the region for the next cartridge. European cartridges target the PAL refresh rate of about 50 Hz. Select the **Controller** row to switch between 3-button and 6-button modes. In 6-button mode, DS **X**, **L**, and **R** send Genesis **X**, **Y**, and **Z**. Hold **L + R + Start** for Genesis **Mode**.
- Tap **[1]** or **[2]**, choose **SAVE** or **LOAD** with the D-pad, and press **A**. The portable C build's versioned `.jsc` files live next to the cartridge. Games with header-declared parallel SRAM use a separate `.srm` file named after the ROM. Older C-port states preserve the cartridge's current SRAM when loaded.

## C sources

- [ROM browser](source/main.c) mounts the SD card through libnds and browses directories using standard file APIs.
- [Bottom-screen interface](source/frontend.c) loads the [recovered menu assets](assets/frontend) into libnds tiled backgrounds and draws the browser, status panel and state slot indicators.
- [ARM7 services](source/arm7/main.c) set up the system FIFO for storage and send input samples to the ARM9.
- [Cartridge loader](source/cartridge.c) reads raw ROMs, decodes SMD blocks, parses the cartridge header and its SRAM range, and computes the Genesis checksum.
- [68000 interpreter](source/m68k.c) reads the reset vectors, runs the supported instructions, handles interrupts, batches repeatable work-RAM loops, and reports the address and opcode where unsupported work stops execution.
- [Genesis bus and VDP](source/megadrive.c) map the cartridge and mirrored RAM, handle three-button and six-button input and Z80 bus requests, schedule vertical and horizontal interrupts, map cartridge SRAM, and access VRAM, CRAM, and VSRAM through the VDP.
- [Z80 bus and timing](source/z80_bus.c) runs the [MIT-licensed C Z80](source/third_party/z80), synchronizes it with the 68000, and delivers the VBlank interrupt pulse. The shared bus exposes YM2612 register and timer status to both guest processors.
- [DS renderer](source/vdp_ds.c) uses tiled backgrounds and hardware sprites for supported modes. It can present interlace mode 2 field by field and switch Plane A maps and sprite tables partway through the frame. It also draws Genesis window rows that cover the full viewport width. For 128-column planes, it maps the visible area into one or two 64-column DS tile maps and switches maps between scanlines. The [bitmap renderer](source/vdp_render.c) handles layouts outside the DS tile, map, or sprite limits. During HBlank, DMA streams the DS scroll registers for each scanline. Raster interrupts handle map and layer changes. Both renderers use recorded per-line vertical scroll when the guest changes it during active display. Vertical Scaling is on by default, as in jEnesisDS 0.7.4. In progressive modes it drops every seventh background line and adjusts each sprite’s vertical position while preserving its height. Turn it off in Configuration to center the unscaled viewport. Interlace mode 2 presents centered fields at native spacing. The bitmap renderer indexes each scanline’s sprites in hardware evaluation order. It composes visible spans in cached RAM and uploads the completed page with DS DMA.
- [Save states](source/savestate.c) serialize the emulated hardware state, verify the cartridge identity, and reject invalid files before restoring the running state. Cartridge SRAM data is flushed on pause, when switching games, and periodically during play.
- The [PSG mixer](source/arm7/psg.c) synthesizes tone and noise on the ARM7. When every channel is muted, it advances the oscillator counters and noise state for the entire block together. The [YM2612 event capture](source/dac.c) records timed 68000 and Z80 writes. The [FM synthesizer](source/arm7/fm.c) renders six independent PCM voices at the original nominal rate of 27,563 Hz. The DS sound hardware plays the six FM voices and a stereo PSG and DAC mix. ARM7 applies each block’s FM routing when that block reaches playback.

The C ROM booted in melonDS 1.1 and loaded Sonic the Hedgehog in both BIN and SMD formats from a subdirectory on the virtual SD card. A host check verified that the loader decoded a cartridge from BIN and SMD into identical bytes and rejected truncated and invalid files.

The C build runs the Genesis backdrop diagnostic in melonDS 1.1. Both captured top-screen colors match the original jEnesisDS 0.7.4 frames pixel for pixel. Sonic's intro, title screen, movement, jumping, and both save slots were tested in melonDS. A restored Green Hill Zone frame matched the frame at the time of saving and matched across both renderers. A separate PSG diagnostic produced audio and muted when paused. melonDS showed both fields in an interlace diagnostic and the separate views in Sonic 2’s split-screen demo. A live Sonic 2 two-player race also draws both views. The tile renderer keeps HBlank interrupts armed across adjacent scanline changes so that the separator can blank one line and the lower viewport can immediately restore the layers. A horizontal-interrupt diagnostic switched vertical scroll partway through the image in both renderers. The VDP still uses synchronous DMA and samples tile data and palettes at frame granularity. PSG registers are sent to the mixer at frame granularity. Run `make check` for host checks covering the CPU, idle-loop scheduling, controller handshakes, Z80 execution and bus access, YM2612 timers, frequency latches, and DAC write timing, VDP interrupts, DMA and port readback, interlaced rendering, scanline scroll and layout changes, tile and sprite priority, save-file validation, and FM and PSG synthesis.

The tile renderer stores the two map pages in VRAM bank E and caches both interlace fields per page in bank A. It uploads tile rows as 32-bit words. The frame scheduler retains overdue guest frames between batches and polls input after at most two. On the same replay, the DS result reached 30.0 guest FPS and native DSi reached 57.5. DSi draw time fell from 84,271 to 48,087 ticks per draw. The host pacing test covers overdue frames, the queue bound, pause, and the PAL rate.

The ARM9 keeps frequently accessed 68000, Z80, and device state in DTCM. Bulk Genesis RAM and VRAM remain in main memory. The interpreters also reuse prefetched Z80 opcodes and take shorter paths through common 68000 branches, cartridge fetches, and work RAM transfers. The 68000 keeps its live registers in DTCM and uses the cartridge prefix that stays mapped when SRAM is enabled.

In the live Sonic 2 two-player race in melonDS 1.1, the BlocksDS C build draws both viewports. It advanced 600 guest frames in 600 VBlanks in native DSi mode, matching the byte-identical devkitARM r20 reference at 59.83 FPS. In 67 MHz DS mode, the same interval fell from 973 to 661 VBlanks, raising the result from 36.89 to 54.31 FPS. This reduced the previous 683-VBlank result (52.56 FPS) by 22 VBlanks. The input script holds Right during the live race. The saved-demo measurements above use a separate fixture.

The r20 source rebuild indexes its 68000 handlers directly by opcode. The BlocksDS C port uses the same lookup structure with C handlers, including common MOVE addressing modes, and keeps horizontal interrupt checks inside the execution loop. Its 65,536-entry table uses 256 KiB of ARM9 main RAM. In matched 600-frame windows in melonDS, the 67 MHz split-screen race improved from 660 to 646 VBlanks (54.39 to 55.57 FPS). The one-player run improved from 671 to 645 VBlanks (53.50 to 55.65 FPS). The r20 reference still completes the split-screen interval in 600 VBlanks.

Z80 FM and DAC timestamps use the continuous guest clock across interpreter slices. The scheduler runs longer slices with the same early checkpoints for bus accesses, PSG writes, and interrupts. The Z80 batches an indexed DAC write when the full instruction sequence is visible in RAM and no interrupt, YM timer, or busy state can affect it. It also finishes common delay loops at the original instruction boundary. In the same melonDS workload, the 67 MHz split-screen race now runs 600 guest frames in 604 VBlanks (59.43 FPS), and the single-player run takes 608 VBlanks (59.04 FPS). Native DSi runs the race at 59.83 FPS. The saved replay's video captures and the CPU, save-state, and timed FM/DAC traces match the previous C build.

The next pass moved idle-loop checks to the 68000 opcodes that can use them and dispatched register ADD and SUB instructions and postincrement word loads directly to their handlers. A masked horizontal interrupt now requests another interrupt check when the guest changes its interrupt mask or enables VDP horizontal interrupts. The renderer reuses scanline layouts and unchanged palettes and transfers sprite attributes to OAM by DMA. The frame scheduler keeps up to eight overdue frames, with input polling after at most two. Sonic also restored an existing C-port save after the audio change. C-port saves track YM2612 registers, held notes, and committed frequencies. The normal frequency latch is shared across both banks and channel 3 has a separate latch, matching the original write handler. The mixer reconstructs notes on load. Older states recover their pitches from the saved register image. The save format does not capture live oscillator phase or envelope position. The FM mixer renders spans at the timed register-write boundaries.

The FM comparison ran the original 0.7.4 ARM7 mixer directly with controlled YM2612 register writes. Across all eight algorithms, enabling register `22h` and the AM bits left the original PCM unchanged. The port now matches that behavior. A patch with zero decay rate enters sustain when the sustain level is zero, as it does in the original. The host checks cover the original PCM hashes for all eight algorithms, three feedback levels, variable block lengths, and muted-operator transitions.

Replaying the same timed YM2612 register writes and render spans for 1,400 Sonic 2 frames through both cores matched all 3,869,784 PCM words across the six voices. All 396 randomized cases that ran to completion in the reference matched. Four additional cases faulted when running the original ARM7 code in the reference harness. The comparison ends at per-voice PCM. Audio timing in a whole-game run still depends on the two builds' register delivery and buffer scheduling.

ARM7 queues up to six guest audio frames and starts mixing after three arrive. The mixer uses four 192-sample hardware blocks and prepares up to three blocks ahead. A cascaded hardware timer tracks the playback position across delayed interrupts. An unprepared block is muted. If the guest queue runs dry, the PSG and DAC mix fades out and the FM state holds at the last guest sample until playback can resume. PSG register snapshots travel with the queued audio.

The experimental Port A release uses the recovered assembly from [`blocksds-port-a`](https://github.com/nextcode4u/jEnesisDS-Decomp-REA/tree/blocksds-port-a). This branch builds the C implementation.
